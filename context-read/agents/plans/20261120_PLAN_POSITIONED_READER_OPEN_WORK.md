# Plan: Positioned Reader — Open Work

**Crates:** `context-trace` (model, navigation, trace), `context-search`
(search), `context-insert` (insertion, seam discovery), `context-read`
(reader), plus consumers in `context-api`, `context-cli`, `context-http`,
`context-mcp` and the context editor.

## Model

The graph is the transitively reduced string-containment graph of all input
strings seen so far.

- Every input document is a token; every atom and every frequent substring
  is a token. Tokens behave like grammar rules producing exactly one string.
- A composite vertex stores a `Composition = [(offset, child)]`: its maximal
  retained proper-child occurrences, sorted, gap-free, without containment.
  Partial overlaps are explicit. Every descendant stays reachable, and
  parent links `(parent, offset)` reach every retained superstring (full
  context relationships).
- A sequence of tokens that is not itself a token is unique in the graph,
  because a repeated sequence would be frequent and therefore a token.
- Gaps, wrappers, slices, accumulation buffers and lookup results are never
  vertices.

## Binding rules

- **No content-keyed index.** The only value-keyed index is atom value →
  atom vertex. Composite vertices are found only structurally, by search
  from atoms through parent links and compositions.
- **Expanded content is debug-only.** Expanded atom sequences may be stored
  only under `#[cfg(debug_assertions)]`. Reading content by traversal
  (`read_interval`) is allowed for export, tests and diagnostics, never in
  an algorithm.
- **Search results are reusable.** Search returns `Response { cache:
  TraceCache, end: MatchResult }`. Insertion and the next adjacent search
  consume it and never repeat the traversal that produced it.
- **Search keeps the legacy architecture.** Only sibling navigation and
  location addressing differ from `context-search/src/legacy`; module
  layout and names mirror legacy.
- **Content uniqueness and overlap agreement are structural.** They follow
  from search completeness and the search evidence, not from lookups.
  Debug/test builds may verify them by traversal.
- **Expectations come from the oracle.** Tests derive expectations only from
  v3 fixture strings (`context-read/tests/fixtures/v3`, generated by the
  ngrams oracle), never from reader output or graph content lookups.
- **Legacy stays fenced.** New code lives at crate roots, not in `legacy`,
  and passes `cargo check -p context-trace -p context-search -p
  context-insert -p context-read --no-default-features --features test-api`.
  Legacy pieces are promoted out of `legacy` only when new code needs them;
  run `--features legacy-tests` whenever legacy code is touched.

## Step 2 — Positioned search (`context-trace`, `context-search`)

### Legacy algorithm being preserved

1. **Seed:** each parent link of the first query token becomes a
   `ParentState` paired with the query cursor (`gen_parent_batch`).
2. **Queue:** min-heap on root width; smallest context first.
3. **Next sibling:** `ParentState::advance_state`; if the root is exhausted,
   raise to the root's parents (`path_raise`, extends the start path).
4. **Compare** (`compare_leaf_tokens`): equal tokens match; different atoms
   mismatch; otherwise decompose the wider side (both on equal width) into
   prefix children and queue them.
5. **First match wins:** the first match clears the queue (uniqueness).
6. **Root cursor:** query and end path advance together; ends with query
   exhausted, mismatch after progress (maximal match), or root exhausted
   (raise and continue from step 2, keeping the best match).
7. **Result:** `MatchResult { PathCoverage (EntireRoot | Range | Prefix |
   Postfix) over start path ↑, root span, end path ↓; checkpointed cursor }`,
   traced into `TraceCache`, returned as `Response`.

### Positional adaptation

| Legacy (rows) | Positioned |
|---|---|
| `ChildLocation(parent, pattern_id, sub_index)` | `OccurrenceLocation(parent, offset, child)` |
| seed batch `parent × (pattern_id, sub_index)` | seed batch `parent × offset` |
| next sibling `pattern[i + 1]` | `start_at(root, end of matched span)` |
| prefix children: head of every row | `prefix_child`: the occurrence at offset 0 (one chain) |
| end path `MovePath`: pop, `index + 1`, else move root | pop steps ending at or before `p`, descend by `start_at`; root exhausted ⇔ `p == width(root)` |
| `path_raise` via row widths | raise `R` through `(P, o)`: span `[s, e)` → `[o + s, o + e)`; push `OccurrenceLocation(P, o, R)` |
| `IndexRangePath` with row entry/exit indices | `RangePath { root, start ↑, end ↓ }` with absolute offsets; entry and exit occurrences may overlap |
| `TraceCache` edges labelled `SubLocation` | same keys (`DirectedKey`), edges labelled by offset |
| `PathCoverage` from row indices | same variants, from `span.start == 0` and `span.end == width(root)` |

**`start_at(R, p)`:** the largest retained token starting at `p` in `R`.
Find the last occurrence `C` with `C.offset ≤ p` (binary search; ends
increase strictly). If `C.offset == p`, return `C.child`; otherwise recurse
into `start_at(C.child, p − C.offset)` and record the step.
O(depth · log(children)), no content access.

A Python prototype of this design (session files, `search_prototype.py`)
matched brute force on all v3 fixtures: 706/706 `start_at` checks, 17,979/
17,979 queries, no ambiguous expectations, no equal-width ties at the first
match.

### Validation on v3 fixtures

In `context-search` tests, loading graphs via
`context_trace::positioned::fixtures::v3_graphs()` and the step 1 name map.

- **Expectation for query `q`:** `k` = longest prefix of `q` occurring in a
  corpus text; `root` = minimal-width fixture vertex string containing
  `q[..k]`, at offset `o`. Assert `(root, o)` is unique; a failure is an
  oracle/model issue, not something to work around in search.
- **Queries per fixture:** every substring of every corpus text; each
  substring extended by every alphabet atom; 300 seeded random strings over
  the alphabet.
- **Per query:**
  - `end.root == name_map[root]`, span `[o, o + k)`;
  - `PathCoverage`: `EntireRoot` iff `o == 0 && k == |root|`, `Prefix` iff
    `o == 0`, `Postfix` iff `o + k == |root|`, else `Range`;
  - end reason: query exhausted iff `k == |q|`, else mismatch;
  - start path ends at atom `q[0]` at offset `o`, end path at `q[k − 1]` at
    `o + k − 1`, every step passes `contains_path`;
  - diagnostic: `read_interval(root, o..o + k) == q[..k]`;
  - the trace cache has entries for every vertex on both paths; up edges
    agree with parent links.
- **Uniqueness counter** (`test-api`): equal-width candidates also matching
  at the first comparison; must be 0 on every fixture.
- **Named cases:** `repeat_abcabca` (`abcab` raises `abca → abcabca`,
  descends into `abca@3`, `Prefix(0..5)`), `repeat_ababa` (`abab` raises
  `aba → ababa`), `seam_bcd` (`bcd`, `abcd`), `repeat_ababab`,
  `repeating_known` (`xyyxy`), `late_retention__2`.
- **Continuation:** chained searches from each `end` checkpoint over every
  corpus text give the same matches as fresh searches at those positions.

**Gate:** all of the above pass on every v3 fixture; no content-keyed
structure in release; `--no-default-features` check green.

## Step 3 — Positioned insertion and seam discovery (`context-insert`)

Replaces row closure for the positioned backend. Inputs are `Response`s;
occurrences and seam candidates come from their trace caches and end paths.

1. Align the accepted match with the committed suffix by offset.
2. Project retained occurrences of both sides into the new owner's
   coordinates (the whole occurrence if a side is a retained proper child,
   otherwise its cover).
3. **Seam discovery:** retained occurrences crossing the seam and not wholly
   inside either side; traverse only beyond what the traces already cover.
4. Deduplicate and prune by containment; keep partial overlaps.

No complement interning, no wrapper vertices, no nested closure, no content
expansion. Insertion from a `Response` that found a complete existing token
yields that token instead of a new vertex. Preserve the accepted evidence
(anchor occurrence, expansion path) for consumers.

**Gate:** merging the oracle covers of overlapping observations reproduces
the oracle composition and parent links of the combined vertex, including
`seam_bcd`; inserting a token removed from a fixture graph from its
`Response` reproduces the fixture.

## Step 4 — Fixed-retention reader (`context-read`)

- Implement `context_read::read(&PositionedGraphRef, impl IntoIterator<Item
  = char>) -> Option<Token>` behind a backend switch; un-ignore the
  positioned lane in `context-read/tests/reader_behavior.rs`.
- The retained identity set per corpus is supplied from the fixture (not
  the offsets); the reader discovers occurrences, accumulates, merges and
  publishes covers itself.
- `RootManager` keeps ownership and commit boundary; the in-progress root
  is an owned positioned cover with a committed width. Append extends the
  width and reconciles affected occurrences; an accepted overlap extends the
  same coordinate space. The root vertex is published or reused only at
  input end.
- One chain of searches per input: each search starts at the checkpoint of
  the previous `Response`; the committed root keeps the `Response` of its
  committed suffix for overlap expansion. A `test-api` counter asserts no
  position covered by a `Response` is searched again.
- First milestone: `abcabca` publishes `abcabca = abca@0, abca@3` without
  allocating `abc`, `bca`, `bc` or any wrapper.

**Gate:** complete-graph equality (`diff` against `to_interchange`) with v3
fixtures for all scenarios under supplied retention.

## Step 5 — Streaming retention and retrospective updates

Retention is append-only across completed inputs: new input may add vertices
and change compositions and links, but never removes a published token or
changes its string; every observed input stays exactly reconstructible.

1. **Lossless observations:** keep each input's atom sequence (explicitly or
   via composite tokens), its boundaries and multiplicity. Occurrence
   evidence refers to input identity and atom offset.
2. **Discovery of untokenized spans** inside and across existing composites.
   Candidate evidence stays separate from vertex storage until the retention
   criterion is met, and is keyed structurally (adjacent tokens/occurrences
   plus input offsets), never by content.
3. **Reconcile hosts on promotion:** find the promoted token's occurrences,
   including in earlier inputs and their hosts (e.g. `vi` inside published
   `vis`); insert where visible; eclipsed occurrences leave that host's
   cover unchanged.

Known facts:
- Retention is **not** monotone within an input (`abcab` retains `ab`,
  `abcabc` does not). Frequency-derived tokens found inside an input stay
  provisional until the input completes; only completed-input boundaries
  are publication points.
- Across completed inputs no retained token was lost in any probe
  (`ngrams/src/tests/retention.rs`); this is empirical, not a proof.

Open questions (answer before choosing data structures):
- Proof that the oracle's retained set is append-only for this observation
  model, or a resolved divergence with the oracle plan.
- Which index or cached evidence is needed beyond lossless input content.
- Bounds on retrospective discovery and on the number of affected hosts
  (measure them).

**Gate:** after each completed input, every published token exists with
unchanged string and every input reconstructs exactly; complete-graph
equality with independent v3 fixtures for successive corpora without
supplied retention, including late retention, duplicate observations and
input permutations where the oracle is order-independent.

## Risks

| Risk | Mitigation |
|---|---|
| Content-keyed shortcuts creep back | Binding rules; step 1 guard; review rule: no algorithm calls `read_interval` |
| Positioned search drifts from the legacy architecture | Mirror legacy modules and names; only `start_at`/`prefix_child`/offset locations differ |
| Uniqueness assumption fails for some oracle output | Unique-expectation assertion and zero tie counter on every fixture (step 2) |
| Repeated traversals over adjacent patterns | `Response` reuse; continuation test (step 2), counter (step 4) |
| Seam occurrences missed when merging side covers | Explicit seam discovery and `seam_bcd` (step 3) |
| Batch frequency disagrees with append-only retention | Step 4 supplies retention; step 5 resolves divergence before cutover |
| Retrospective updates unbounded | Measure affected hosts before choosing data structures (step 5) |
| Large blast radius of the model change | Backends coexist until step 6 |

## Non-goals

- Changing oracle semantics (owned by the ngrams plan).
- Storing gaps, wrappers or local layouts as vertices.
- Persistence format optimizations beyond what v3 requires.
