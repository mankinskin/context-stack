# Positioned n-gram oracle: implementation and test plan

This is the execution checklist for the [oracle design](20261118_PLAN_POSITIONED_COMPOSITION_ORACLE.md). It supersedes that document's implementation phases and test checklist. It covers the offline oracle and the compatibility work needed to land it independently. The [reader plan](../../../context-read/agents/plans/20261118_PLAN_POSITIONED_COMPOSITION_READER.md) owns streaming retention, navigation, and the final cutover of row-based consumers.

## Progress

- [x] A–C implemented: deterministic selection, positioned composer, v3 output and validator, `parse_corpus` (v3) and `parse_corpus_legacy`.
- [x] D cutover stage: legacy callers explicit, 51 v3 fixtures in `context-read/tests/fixtures/v3`, fixture validation recomputes them from the oracle.
- [ ] D post-reader stage: migrate reader/workspace consumers to v3, then delete the legacy pipeline and v2 lane.

## 1. Contract and cutover shape

```text
validated corpus -> exhaustive containment and occurrence counts
                 -> frequency selection and frozen retained set
                 -> maximal positioned child covers
                 -> validated v3 snapshot
```

- Retain exactly corpus roots, atoms, and frequency-selected tokens. Preserve input boundaries, order, and multiplicity in `corpus`, even when multiple texts share one root vertex. Don't concatenate inputs for counting. An atom is a Rust `char` (Unicode scalar), not a UTF-8 byte or a grapheme cluster; do not normalize input text.
- A composite's authoritative decomposition contains every maximal **proper** retained occurrence. Its entries are `(atom_offset, child)`. Drop duplicates and wholly contained occurrences, keep partial overlaps, and retain separate offsets for repeated occurrences of one child. Atoms have empty compositions. The union covers each position, and strict width descent makes reconstruction terminate. When reading overlapping children, project into owner coordinates rather than concatenating.
- No wrapper or gap promotions, compatibility tokens, or compulsory row packing in v3. Former wrapper/gap content is a vertex only if independently retained. If a consumer needs rows, derive them later as local views of the owner's occurrences and ranges; no such layout is necessary for the oracle cutover.
- Keep the working containment `Hypergraph` private to selection/composition or clearly marked diagnostic. The public semantic result is a positioned table, not a row `Hypergraph`. Reverse occurrence links, if needed by a consumer, are derived from `(owner, offset, child)`; they are not stored in v3.
- Ship v3 without waiting for the reader: `parse_corpus` and the `ngrams` executable become v3 together. Move existing v2 graph construction behind `parse_corpus_legacy` with a distinct `LegacyParseResult`. Preserve existing v2 output types under an explicit `output::legacy` module and migrate their callers in the same patch. Use distinct `PositionedGraphData`/`PositionedGraphSnapshot` and `POSITIONED_FORMAT_VERSION` in `output` to prevent swapping shapes by accident. Do not retry failed v3 requests via v2.

## 2. Implementation sequence

### A. Fix and test the input and frequency boundary

- [ ] In [`graph/vocabulary/mod.rs`](../../src/graph/vocabulary/mod.rs) and [`graph/containment.rs`](../../src/graph/containment.rs), reject an empty corpus or any empty text in the v3 library entry point before enumeration. Compute widths in atoms. Construct width-minus-one prefix/suffix and endpoint atoms at character boundaries; keep the existing elementary two-pattern shape for widths greater than two and the single atom-pair pattern for width two. Resolve **every** full input through `vocab.ids` after enumeration to populate `roots`, independent of where the content was first interned. Keep occurrences keyed by `(text index, atom offset)`.
- [ ] Make containment progress use the number of enumerated windows (sum of `n * (n + 1) / 2` per nonempty input of atom width `n`), not a maximum byte length. Report a `Compositions` phase with a nonzero total and enter `Finished` only after successful composition and validation. Keep wrapper/partition status only for legacy. Check cancellation before starting and during new composition work; propagate `CancelReason` without returning or serializing a partial graph.
- [ ] In [`graph/labelling/frequency.rs`](../../src/graph/labelling/frequency.rs), seed the selected set with **all** roots and atoms before testing any candidate. Visit all remaining composites once in decreasing width (stable content order for ties); don't rely on expanding only unlabelled roots or on [`SortedQueue`](../../src/graph/traversal/queue.rs)'s adjacency dedup. Reuse the existing relative-count predicate, not a raw occurrence threshold: a candidate needs a contributing selected ancestor with strictly fewer occurrences.
- [ ] Audit the nested [`FrequencyCover`](../../src/graph/utils/cover/frequency.rs) as well as the outer pass. Its current parent map iteration is not a scheduling contract: a parent that contributes earlier can cover positions a later parent would have contributed. For v3, make the breadth-first order explicit: at each traversal depth process parent states by `(ancestor content, candidate offset)`; preserve the rule that an ancestor with new occurrences ends that branch and a non-contributor is expanded. Don't use generated IDs or text indices as tie-breakers. This defines the formerly unspecified tie order; document any selected-set changes on production fixture corpora instead of treating them as format-only changes. Keep legacy selection and cache artifacts out of the v3 path.
- [ ] In [`graph/labelling/mod.rs`](../../src/graph/labelling/mod.rs), run v3 on a fresh containment vocabulary and a fresh selection. Bypass v3 image-cache reads and writes for this migration: the current cache uses the corpus name and can contain wrapper labels or different inputs. Leave cache policy for legacy alone; a future v3 cache must validate phase, algorithm version, and complete corpus identity.

**Gate:** input/count tests and retained-set permutation tests pass without running composition. Cached and uncached legacy artifacts cannot affect v3.

### B. Build covers from immutable input

- [ ] Add `src/graph/composition.rs` with a fallible composer taking `&Vocabulary`, a read-only retained set, and cancellation/progress handles. Return covers keyed by existing identities; no interning, label mutation, graph reparenting, or lookup in partially built output. Obtain positioned prefix/suffix by content or verified containment offsets; never treat an arbitrary row slot as an atom offset.
- [ ] Compute in increasing width. An atom has an empty cover and exposes itself. For each composite `V`, take the exposed occurrences of its width-minus-one prefix and those of its width-minus-one suffix shifted by one. Normalize their union: sort by start ascending and end descending, then keep an interval only if its end is strictly greater than the greatest end seen. Within one owner a positional span identifies exactly one content string, so this drops both duplicates and contained intervals without dropping partial overlaps. Even when prefix and suffix have the same identity, evaluate both offsets. Store the resulting proper cover for retained `V`. To its parents, retained `V` exposes only itself; unretained `V` exposes its normalized cover.
- [ ] Test the recurrence against **direct substring enumeration**, not only the old `ChildCoverPass`: for each retained owner enumerate every `(start, end)` proper span using atom indices, filter by the separately supplied retained set, then drop spans via a pairwise containment test. The reference must not use the recurrence, production normalization, or containment edges. Every proper span is inside the prefix or suffix; pruning an enclosed occurrence in either cannot make it maximal in the owner. This is why the recurrence and the enumeration should agree.

**Gate:** compare full cover tables with selection fixed. Process same-width working entries and output owners in deliberately reversed order as well; labels and covers must be unchanged. Test cancellation directly at the builder boundary, not by depending on timing or a racing thread.

### C. Add v3 interchange, then switch public entry points

- [ ] In [`output.rs`](../../src/output.rs), serialize v3 as `{ "format_version": 3, "corpus": [...], "vertices": { "<content>": [[<atom_offset>, "<child>"], ...] } }`. Use a `BTreeMap` for content and a `Vec` for occurrences so invalid duplicates/order are visible to validation. Reject duplicate vertex keys at decode rather than letting map insertion silently overwrite them. Emit entries in `(offset, child atom width)` order. Do not serialize IDs, reverse links, containment data, or derived layout.
- [ ] Validate version, corpus/root presence, nonempty content, empty covers only for atoms, known and strictly narrower children, checked span bounds and content equality, canonical order, no duplicate or contained occurrences, and complete positional coverage. Errors should name the owner and offending entry or uncovered position where applicable. Keep this structural validator separate from oracle verification: also assert the exact retained set and compare maximal covers to the independent enumerator in semantic tests. A full, valid cover can still omit a maximal overlapping occurrence.
- [ ] In [`graph/mod.rs`](../../src/graph/mod.rs), wire v3 `parse_corpus` to validate input, enumerate, select, compose, and return the validated `PositionedGraphData` in `ParseResult.graph`. Keep any working `containment`/`labels` access only for diagnostics, with labels explicitly meaning the frozen retained set. Isolate `label_wrap`, `label_part`, `partitions/`, and `utils/dedup/` behind the legacy path; don't delete them while a consumer still needs them. In [`graph/trace.rs`](../../src/graph/trace.rs), replace v3 partition diagnostics with retained-set and owner/offset cover diagnostics; keep old diagnostics legacy-only.
- [ ] In [`main.rs`](../../src/main.rs), remove the `GraphData::from_graph` conversion and build `PositionedGraphSnapshot` directly from the v3 parse result. Preserve inline stdout, scenario input/filename validation, per-scenario files, and stderr-only diagnostics. There is no v2 CLI mode in this plan. Keep existing batch semantics (a failure can leave earlier valid files); validate each snapshot before opening its output file. Update [`ngrams/README.md`](../../README.md) with the v3 schema, a partial-overlap example, a separate v3 fixture destination, and the legacy-only qualification on order dependence.

**Gate:** `cargo test --release -p ngrams` passes, including exact v3 CLI assertions, round-trip and corruption tests. No v3 call path reaches wrapper or partition code.

### D. Migrate consumers in two stages

- [ ] **With the oracle cutover:** in [`context-api/src/workspace/manager.rs`](../../../context-api/src/workspace/manager.rs), keep `create_workspace_from_ngrams_text` explicitly on `parse_corpus_legacy` while it stores a `HypergraphRef`. Document it as provisional; do not convert v3 back to synthetic rows or change the workspace persistence format in this patch. Inventory API dispatch/editor callers of this workspace operation and verify they still build. [`context-api/src/commands/compare.rs`](../../../context-api/src/commands/compare.rs) uses a separate context graph snapshot type; don't replace it with oracle v3 by name alone.
- [ ] **With the oracle cutover:** migrate [`context-cli` oracle integration tests](../../../tools/cli/context-cli/tests/integration/ngrams_oracle_tests.rs) that read `parse_result.graph` as a row snapshot to the explicit legacy API; mark those comparisons provisional. Replace v3 oracle self-checks with independent expected tables in `ngrams`, not equality against the same snapshot. In [`context-read/tests/support/mod.rs`](../../../context-read/tests/support/mod.rs), keep v2 fixture decoding/graph seeding explicit (`output::legacy`) and add a separate v3 loader/validation path. Row-dependent [`reader_behavior`](../../../context-read/tests/reader_behavior.rs) and [`cursor` tests](../../../context-read/src/tests/cursor.rs) stay on v2 until the reader can produce positioned covers.
- [ ] Generate v3 fixtures under `context-read/tests/fixtures/v3/` from the existing [`scenarios.json`](../../../context-read/tests/fixtures/scenarios.json) using the tested oracle; leave checked-in v2 artifacts untouched. Extend [`fixture_validation.rs`](../../../context-read/tests/fixture_validation.rs) to check one v3 fixture per manifest entry, exact corpus order and multiplicity, and snapshot validity. Verify regeneration produces no diff; review changes against hand expectations rather than updating golden files to agree with the reader. Document both fixture paths in [`context-read/README.md`](../../../context-read/README.md).
- [ ] **After positioned reader/workspaces land:** switch reader and CLI comparisons to full content-keyed v3 equality (both missing and extra vertices and occurrences), and migrate workspace creation, comparison, and affected snapshot consumers to positioned data. Then remove the v2 fixture lane, legacy API/types/status/trace and wrapper/partition/dedup implementation after checking that no callers remain. Do not make reader cutover or append-only/batch retention parity a prerequisite for the offline v3 oracle.

## 3. Test changes and concrete acceptance cases

| Test location / lane | Required assertions |
|---|---|
| [`src/tests/mod.rs`](../../src/tests/mod.rs), containment/frequency | Keep useful containment and frequency expectations; separate legacy wrapper/partition expectations from v3. Replace `parse_corpus` smoke checks based on row graph IDs or nonzero vertex counts with exact v3 results or declared properties. Test both orders of `["abc", "xabc"]`: `abc` is a root even when first interned as a substring, `abc` has `[a@0, b@1, c@2]`, and `xabc` has `[x@0, abc@1]`. Test `["a", "b", "a"]`, empty corpus, mixed empty/nonempty texts, and duplicate observations `["aaaa", "aaaa"]` (`aa` occurs six times at three offsets in each input). Use `["é🙂é"]` to require offsets `0, 1, 2` rather than byte offsets. |
| Focused frequency-cover tie test | With labels pinned to include `xab` and `aby` for `["xaby", "xabz"]`, `aby` contributes to `ab` first and the predicate selects `ab` (one occurrence vs. two). With `abx` and `yab` pinned for `["yabx", "zabx"]`, `abx` contributes both positions first and `yab` cannot justify `ab`. Rebuild with the inputs reversed and require the same decisions. This isolates the specified tie rule from the outer selection pass. |
| New focused positioned tests | `abcabca`: exact vertices `{a, b, c, abca, abcabca}` with `abca` covering its atoms and root `[abca@0, abca@3]`. `ababa`: exact vertices `{a, b, aba, ababa}` with `aba` covering its atoms and root `[aba@0, aba@2]`. Assert both positions survive and the omitted legacy tokens are absent. A fixed-retention case for `aaaa` with `{a, aa, aaaa}` must retain `aa@0`, `aa@1`, and `aa@2`; the middle occurrence is required even if it is unnecessary for positional coverage. |
| [`src/tests/hash_order.rs`](../../src/tests/hash_order.rs), regression | Replace the legacy queue adapter in the normal test path with two independent v3 checks for `["subdivision", "visualization"]`: first hold selection fixed and vary internal build/owner iteration; then reverse corpus inputs and test the full pipeline. Expect `vis` to have `[v@0, i@1, s@2]`, with no synthetic `vi`. Compare retained *content* first, then full covers, not just `vis`. Compare `.graph`, not the ordered snapshot `.corpus`. If retaining the old failing reproducer for diagnostics, quarantine it as ignored and explicitly label it legacy. |
| Generated checks | Enumerate binary single texts of widths 1–8 and deterministic sampled multisets of 1–3 texts over small alphabets (including repeats and a text that is another input's substring). Compare v3 selection and full covers under every distinct permutation; compare each cover with direct enumeration for the selected set and reconstruct the root atoms by position. Also test the composer with independently supplied retained sets so a matching selection error cannot mask cover errors. Keep a bounded set in normal tests; put the larger sweep in a named ignored release test with reproducible failure inputs. |
| v3 output tests | Round-trip an overlapping snapshot containing the same child at distinct offsets and test deterministic bytes for identical inputs. Reject wrong version, v2 row arrays, duplicate vertex keys/entries, unsorted entries, unknown/equal-width children, overflowing/out-of-range offsets, span/content mismatches, uncovered positions, contained intervals, and missing corpus roots. Demonstrate the validator's limit with `ababa: [aba@0, b@3, a@4]` when `aba` is retained: structural validation passes, but semantic verification must find the missing `aba@2`. |
| [`tests/cli.rs`](../../tests/cli.rs) | Decode both inline and file outputs as v3, preserve original order/multiplicity, and replace the alternative-decomposition assertion with the exact overlapping cover of `abcabca`. Keep negative scenario/flag and no-output-on-invalid-input assertions; add an atom-only success case. Verify diagnostics do not contaminate stdout and identical ordered input emits identical JSON across independent invocations. |

## 4. Completion gates

1. Oracle: `cargo test --release -p ngrams` plus `cargo test --release -p ngrams --lib positioned_corpus_sweep -- --ignored` after adding that test. For a fixed retained set, independent enumeration must match every cover. For equivalent corpus permutations both the retained set and positioned graph must match, although the serialized `corpus` field retains the supplied order.
2. Fixtures: regenerate with `cargo run --release -p ngrams --bin ngrams -- --file context-read/tests/fixtures/scenarios.json --out context-read/tests/fixtures/v3`, then run `cargo test --release -p context-read --test fixture_validation`. Confirm the v2 files have not changed.
3. Downstream: run the existing context-read and context-cli suites, including the provisional row comparisons, and `cargo build --workspace --all-targets --exclude context-editor-kernel --exclude sandbox-app` in the Linux codespace. Verify workspace creation still uses its documented legacy backend. Use an editor-capable build environment when migrating its consumers.
4. The v3 oracle is complete when the default code path publishes validated positioned covers independently of traversal order and without wrapper/gap vertices. Legacy removal is a separate completion gate after no row consumer requires the legacy oracle.
