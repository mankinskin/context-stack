### Benchmark group design and limitation (documented, not acted on)

wgpu compute/render dispatch (the actual ray-march compute pass, splat sort/rasterise passes, force-compute) requires a live `RenderDevice`/`RenderQueue` wired through Bevy's render sub-app and a window/surface — not portable to a headless Criterion harness. Per the waypoint's documented-limitation allowance, all three benchmarks measure only the deterministic CPU boundary feeding those GPU stages:

1. `svo_dirty_range_processing` — `VoxelWorld::set_voxel` (1,728 voxels, 12³ cube, depth 7) + `VoxelWorld::take_dirty_ranges` — the per-frame CPU step gating `svo_paged_upload_system`.
2. `svo_paged_upload_prepare` — `PageManager::build(&voxel_world, None)` — packs the CPU SVO into the GPU node buffer + page table consumed by both the ray-march compute pass and (via the shared FRONT buffer) splat generation. **No pure CPU-only splat-generation function exists independent of Bevy ECS systems** — `particle_splat::simulate_particles` takes `Res<Time>`/`ResMut<ParticleSystem>` and is a private (non-`pub`) system function, so it cannot be benchmarked directly from an external `benches/` binary without a visibility or architecture change, which is out of scope for this waypoint. `svo_paged_upload_prepare` stands in for "splat preparation" per this documented limitation.
3. `ray_march_uniform_prepare` — `GpuRenderUniforms::from_params(...)` — the per-frame CPU uniform pack consumed by the ray-march compute shader.

No GPU timing is measured or invented.

### Harness mechanism (explicit, reproducible)

`verify-visual-baseline.mjs` spawns `trunk serve --port 8090` (matches the committed `Trunk.toml`), polls the URL until it responds (60s bound), connects headless Chromium (Playwright, pinned `1.62.1` to reuse an already-cached local Chromium build and avoid a network browser download), waits for the sandbox `<canvas>` to attach, awaits 30 `requestAnimationFrame` callbacks (bounding at least one full `svo_paged_upload_system` → `double_buffer_swap_system` cycle per ARTIFACTS.md §7's determinism requirement), screenshots the canvas, and compares its exact SHA-256 byte hash against the committed baseline — creating the baseline on first run. A missing `trunk` binary, a server that never becomes ready, a browser/canvas that never appears, or a hash mismatch is reported as an explicit `BLOCKER:` message with a non-zero exit code; nothing is silently skipped.

**Documented limitation**: comparison is exact-byte SHA-256, not a perceptual/tolerant pixel diff. Any renderer nondeterminism (GPU driver, AA jitter, font hinting, OS) would register as a mismatch even without a functional change. A tolerant perceptual diff is out of scope for this waypoint (no defect-fix or optimization work is in scope here); W5/W6 may need to revisit this if cross-environment nondeterminism appears.
